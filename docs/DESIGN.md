## 1. 这个项目在做什么

三样东西叠在一起：

| 层 | 内容 | 作用 |
|---|---|---|
| **可编程生物** | 卡片式规则（条件 + 动作 + 优先级） | 让玩家**能理解、能修改**生物行为，而不是看黑箱 |
| **生态箱模拟** | 连续 2D 世界、食物斑块、水域、捕食 | 提供搏斗的舞台和选择压力 |
| **演化引擎** | 参数 / 规则 / 器官三层变异 + 元演化 | 让规则自己长出你没写过的行为 |

**核心理念：你不需要设计"好玩的行为"，你只需要设计"代价与收益的结构"，行为会自己涌现。**

这条理念直接决定了实现的优先级：**器官开销、代谢公式、捕食收益这些数字，比任何 AI 算法都重要。**
整个项目 80% 的调参时间花在这几行公式上，而不是花在变异算子上。

## 2. 三层架构

```
┌──────────────────────────────────────────────────────┐
│  UI 层  (Terrarium.App, WinForms + GDI+)              │
│   TerrariumCanvas │ RuleEditorPanel │ InfoPanel       │
│   ChartPanel      │ EnvironmentPanel                  │
└───────────────┬──────────────────────────────────────┘
                │  SimSnapshot（只读值拷贝）  ↑
                │  编辑命令（ReplaceGenome/Inject） ↓
┌───────────────┴──────────────────────────────────────┐
│  模拟内核 (Terrarium.Core, 纯 C#, 无 UI 依赖)          │
│   World · Creature · Genome · Rule · Mutator · Rng    │
│   固定步长 · 确定性 · 单线程                            │
└───────────────┬──────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────┐
│  无头实验台 (Terrarium.Headless, 控制台)               │
│   多倍速跑演化 / 多种子对照 / 导出 CSV 与冠军基因组      │
└──────────────────────────────────────────────────────┘
```

**为什么内核绝不引用 UI：**

1. **能无头加速**：`Terrarium.Headless` 可以几千 tick/s 地跑演化实验。生态参数的平衡
   不可能靠看画面调出来 —— 只能跑几十组对照看曲线。
2. **能验证确定性**：同种子 + 同 tick 数必须产出逐字节相同的世界（见第 8 节）。
3. **不会被 UI 框架绑死**：将来换渲染层（甚至换 MonoGame）不用重写一行模拟逻辑。

**线程模型刻意做到最简：**

- 模拟线程独占 `World`，`Simulation` 内部一把锁。
- `RunBatch` 是**每 tick 加一次锁**，所以 UI 可以在 tick 之间插进取快照，
  开"极速"时界面不会整个卡死。
- UI 只通过 `Snapshot()` 拿不可变快照，永不触碰 `World` 本体。

> ⚠️ 一个踩过的坑：UI 为了显示"这只生物此刻看到什么"需要重建一次感知数据。
> 最初这个函数走了 RNG（噪声传感器），结果**每次点开详情面板都会消耗随机数流、
> 把后续演化轨迹整个改掉**。修法是把噪声改成 `Hash(个体Id, tick)`。
> 教训：任何"只读"的观察接口都必须保证零副作用。

## 3. 世界与资源

- **连续 2D 坐标**（不是格子）：生物能斜着跑、能绕圈，观感自然得多。
- **瓦片化的资源层**：食物、肥力、水域按 `TileSize`（默认 20 单位）分格。
  兼顾了连续空间的行为手感和格子化的生态可计算性。
- **空间哈希网格**（格子 40 单位）做邻居查询，把 O(n²) 压到近似 O(n)。
  配合**扩张方环搜索 + 提前退出**：多数个体在几环内就能找到目标，不必扫满视野。
- **地形用 fBm 噪声生成**，阈值按目标占比取分位数，所以"肥沃占比 / 水域占比"
  是精确可控的，不受噪声分布形状影响。

### 资源循环

```
光照 → 肥力地块 → 食物（logistic 再生）
                      ↓ 吃
                   生物能量
                      ↓ 死亡 / 被猎杀
                   尸体回到地块食物池
```

食物再生用 **logistic 曲线** `food += rate·(0.25+food)·(1-food/cap)`：
空地块长得快，接近上限变慢。这自然形成"斑块被吃秃 → 慢慢恢复"的节奏，
比线性再生有趣得多。

### 水域是一个真实生态位（关键设计）

最初水域只是"无鳃生物下水会掉能量"的惩罚区。结果是**所有生物都躲开水，
水域等于浪费的地图，而且长期演化必然塌缩成单一物种**（竞争排斥）。

改成「**水里长满只有带鳃生物能安全采食的水生植物**」之后：

| 水域占比 | 共存物种数 | 6 万 tick 内猎杀次数 |
|---|---|---|
| 0（无水） | 1–8（不稳定） | 5771–12224 |
| **0.18** | **4–8** | **11239–24169** |

多物种共存让"敌人"永远存在，捕食才能成为一个稳定生态位。
**这是整个项目里性价比最高的一个设计改动。**

## 4. 生物模型

```
Creature
├── 状态  位置 / 朝向 / 能量 / 生命 / 年龄 / 中毒 / 繁殖冷却
├── 器官  int[10]，每级 0–5
├── 规则  List<Rule>（有序 = 优先级）
└── 谱系  物种Id / 代数 / 色相 / 体型缩放
```

### 4.1 器官：演化的物理基础

**每个器官都是「能量开销 ↔ 功能」的交换，而且器官之间互相耦合。**

| 器官 | 功能 | 1 级开销 | 体重 | 耦合副作用 |
|---|---|---|---|---|
| 腿 | 速度 (1.0+0.85·L) | 0.0080 | 0.55 | 体重拖慢自己 |
| 眼 | 视野 (45+45·L) | 0.0090 | 0.10 | — |
| 牙 | 攻击 (+3.2·L) | 0.0100 | 0.50 | — |
| 甲 | 减伤 (min 45%, 9%·L) | 0.0150 | 2.00 | **极重** |
| 胃 | 能量上限 (+18·L) / 消化效率 | 0.0045 | 0.60 | — |
| 藻胞 | 光合自养 | 0.0020 | 0.30 | 夜里失效 |
| 毒腺 | 攻击附加中毒 | 0.0090 | 0.40 | — |
| 生殖腺 | 繁殖阈值 (−8·L) | 0.0120 | 0.50 | — |
| 鳃 | 水域生存 | 0.0070 | 0.30 | 陆地上纯浪费 |
| 棘 | 反伤 (10%·L) | 0.0080 | 1.00 | 加体重 |

**开销是超线性的**：`开销 = 基础 × 等级^1.65`。

> 这是让「特化」能赢过「什么都点满」的**关键**。
> 开销如果是线性的、而收益是递减的，最优解永远是全能型 ——
> 全场生物长得一模一样，没有任何生态位可言。
> 实测把指数从 1.0 提到 1.65，平均体重从 5.9 降到 2.0–3.4，
> 物种从 1–2 个变成 4–8 个。

**关键推导公式：**

```
体重      = 1 + Σ(等级 × 体重系数)
最大速度  = (1 + 0.85·腿) × 2.2 / (1 + 体重)
实际减伤  = min(0.45, 0.09·甲)
能量上限  = 70 + 18·胃
生命上限  = 22 + 7·体重 + 5·甲
每tick开销 = 基础代谢(0.6+0.4·体重) + Σ器官开销 + 规则维持成本
繁殖阈值  = max(24, 60 − 8·生殖腺)
```

> ⚠️ **最容易犯的错**：繁殖阈值必须低于能量上限。
> 第一版阈值 110、创始生物能量上限 88 —— 结果 6400 tick 里出生数为 0，
> 所有初代同时寿终、种群直接灭绝。**阈值和上限必须对着调。**

**规则也要收维持成本**（超过 3 条后每条 0.003/tick）。
没有这一项，规则数会无成本地膨胀：实测从 5 条一路涨到 13.6 条，
其中大半是永不触发的垃圾规则在做中性漂移，玩家打开详情面板只看到一堆噪声。
生物学上也站得住脚 —— 神经组织是昂贵的。

### 4.2 传感器池（20 个）

全部归一化到 `[0,1]` 或 `[-1,1]`。**这是刻意的**：变异时的数值微扰需要一个统一尺度，
否则"距离 0–270"和"能量百分比 0–1"用同一个 sigma 去扰动，前者等于没动、后者直接跑飞。

```
永远是 · 我的能量% · 我的生命% · 我的年龄%
最近食物距离 · 最近食物方位 · 最近敌人距离 · 最近敌人方位
同族数量 · 周围敌人数量 · 周围拥挤度 · 我的战力
脚下食物量 · 我在水里 · 我有鳃 · 我正在中毒
我撞到边界 · 随机噪声 · 我的体重 · 昼夜相位
```

方位类传感器是**相对角 / π**：−1 = 正左后方，0 = 正前方，1 = 正右后方。

### 4.3 动作池（11 个）

```
什么都不做 · 移动 · 冲刺 · 攻击最近敌人 · 吃脚下的食物
繁殖 · 原地休息 · 生长器官 · 退化器官 · 转向 · 释放信息素(预留)
```

需要方向的动作配一个**方向选择器**：正前方 / 随机 / 最近食物 / 最近敌人 /
远离最近敌人 / 最近同族 / 远离最近同族 / 世界中心 / 保持朝向。

> **核心约束：规则只能通过传感器和动作与世界交互，不允许任意脚本。**
> 正因为它是封闭枚举，规则图才能被安全地随机变异、交叉、可视化、并解释给玩家看。
> 一旦允许"写代码"，这三件事全部做不了。

> ⚠️ 另一个坑：**还没实装的动作用纯中性噪声污染演化**。
> "释放信息素"当初是个空操作，生物既不会因此变好也不会变差，
> 于是它会在基因组里越积越多。修法是把未实装的动作从随机变异池里排除
> （`ActionTable.MutablePool`），等真正实装信息素场之后再放回去。

### 4.4 规则

```
优先级 1  当 [脚下食物量] > 0.12                        → 吃脚下的食物
优先级 2  当 [最近敌人距离] < 0.22 且 [我的生命%] < 0.70  → 移动 → 远离最近的敌人
优先级 3  当 [我的能量%] > 0.82                          → 繁殖
优先级 4  当 [最近食物距离] < 1.0                        → 移动 → 最近的食物
优先级 5  当 [永远是]                                    → 移动 → 随机方向
```

**每 tick 从上往下求值，第一条条件全部满足的规则触发，其余忽略。**
这是经典的 subsumption 架构 —— 比"所有规则都执行"好调试、好演化，
也让玩家能从视觉上理解"它为什么这么做"（选中的生物头顶会亮一条指示线）。

一条规则支持 1–4 个条件（AND）、1–3 个动作。

## 5. Tick 主循环

固定步长，真实时间基准 **20 tick = 1 秒**。

```
Step():
  1. BuildGrid()          重建空间哈希（用上一 tick 结束时的位置）
  2. RegrowFood()         食物按 logistic 再生
  3. for 每个生物（从 Tick%N 轮转起始，消除"列表靠前永远先动手"的偏差）：
       a. Sense()           计算感知数据
       b. Think()           从上往下求值，选中第一条满足的规则
       c. Execute()         按顺序执行该规则的所有动作
  4. Metabolize()         基础代谢 / 光合 / 溺水 / 中毒 / 衰老 / 死亡判定
  5. CollectDead()        移除死者，尸体转成地块食物
  6. 加入本 tick 出生的幼体（人口上限内）
  7. Tick++
```

**动作执行细节（都是踩过坑之后定下来的）：**

- **移动**：先以 0.35 rad/tick 转向目标，再沿朝向位移。瞬时转向会让画面上生物"抽搐"。
- **攻击**：
  - 够得着 → 造成 `(0.35 + 0.62·牙) × (1 − 目标减伤)` 伤害，攻击者即时回收 30%。
  - **够不着 → 以 1.0–2.0 倍速扑咬**。
    > 这一条是"搏斗"能不能发生的分水岭。最初追击速度 0.9×，
    > 而逃跑是 1.0× —— 捕食者永远追不上猎物，4 万 tick 内猎杀数为 **0**。
    > 改成 2.0× 之后，猎杀数立刻变成几千。
- **击杀收益** = `猎物剩余能量 × 0.70 + 猎物体重 × 18`。
  > 平移到狩猎：猎物身上那点余粮通常**不值一条命**，
  > 真正值钱的是它这具身体本身。没有这个"按体重"的固定奖励，
  > 捕食在能量上永远亏本，捕食者也永远不会演化出来。
  > 但也不能太高 —— 试过 `体重×25`，捕食者指数爆炸、把猎物吃绝、然后自己饿死。
- **繁殖**：能量达到阈值才成功，付出 62% 阈值、后代拿到其中 46%。
  后代基因组经过变异，有 2.2% 概率另立新物种。
- **生长/退化器官**：留在动作池里，让"后天改变身体"也成为可演化的策略。

## 6. 能量经济：关键数字

默认参数下的稳态（3200×2000 世界，约 420 初始个体）：

| 指标 | 值 |
|---|---|
| 人口 | 300–1400（随参数和种子波动） |
| 平均能量 | 36–48% 上限 |
| 每 tick 开销 | 0.05–0.15 |
| 平均世代时间 | 200–900 tick（10–45 秒实时） |
| 主要死因 | 饿死 > 被猎杀 > 寿终 |
| 速度 | 约 765 tick/s（8 核并行，约 500 个体） |

**调参时的心算模型**（很有用）：

```
能量供给/ tick = 地块数 × 各地形食物容量均值 × 食物再生率 × 42
种群平衡      ≈ 供给 / 平均每tick开销
```

算出来会发现"理论供给"通常远大于实际消耗 ——
因为**食物只长在踩得到的肥沃地块上，长满了就不长了**，
而且 7% 的岩石地块是采集不到的。
所以真正限制种群的不是总供给，而是**可达的觅食效率**。

## 7. 演化引擎

### 三层变异算子

| 层 | 频率 | 内容 | 负责 |
|---|---|---|---|
| **参数微调** | 高 | 规则阈值 ± 高斯、方向/力度重采样、器官 ±1 | 精修 |
| **规则变异** | 中 | 换传感器 / 换算子 / 换动作 / 增删条件 / 增删动作 | 想出办法 |
| **结构变异** | 低 | 插入规则 / 删除规则 / **交换优先级** / 复制规则 / 新物种分化 | 改变策略 |

`交换两条规则的优先级`这一条经常产生巨大的行为变化，成本却几乎为零 ——
它是整个变异池里性价比最高的算子。

阈值微扰的 sigma **按传感器的量程比例取**（span × 0.11），
这样"方位 −1..1"和"距离 0..1"的扰动强度才有可比性。

### 元演化：让"进化能力"本身也进化

```
MutationRate       (0.02 – 1.20)
RuleMutationRate   (0.02 – 1.20)
```

这两个值也是基因，在对数空间做微扰。实测在稳定环境里它们会从 0.35 一路降到
**0.13–0.29** —— 稳定期的保守化，是教科书级的演化现象。

### 交叉（有性生殖，MVP-3 预留）

按"规则签名"做同源对齐再交叉装填，而不是简单对半切。
简单对半切会把规则列表切得面目全非，后代行为基本等于随机重采样。
器官取双亲平均，元基因取平均。

### 初始种群：六个生态原型

创始种群**不是一群一模一样的原生生物**，而是六个生态原型：

| 原型 | 器官 | 策略 |
|---|---|---|
| 食草者 | 腿1 眼1 胃1 | 均衡通用，生态基准 |
| 疾行者 | 腿3 眼2 胃1 | 靠速度活命 |
| **掠食者** | 腿2 眼2 牙2 胃1 | 把别人的身体当饭吃 |
| 甲士 | 腿1 眼1 甲3 棘2 胃1 | 重装甲硬碰硬 |
| 光合者 | 腿1 眼1 藻胞3 胃1 | 不觅食，晒太阳 |
| 群居者 | 腿1 眼2 胃1 生殖腺2 | 跟同族走，分摊风险 |

> **为什么不从单一祖先开始：** 如果所有人共用一套"吃—走—生"规则，
> 演化就得靠随机规则变异从零**发明**出捕食、装甲、光合这些策略。
> 这个搜索空间太大，几十万 tick 都未必撞得出来（实测：120000 tick 内猎杀数近乎为 0）。
> 给一组起点不同的原型，世界从第 0 tick 就有真实的生态位竞争，
> 演化立刻有原材料可用。
>
> 每个物种内部的个体之间还会做一次**轻微抖动**（只微调器官和阈值，不碰规则结构），
> 否则同物种完全一样，自然选择一开始就无材可选。

## 8. 确定性：为什么它必须可复现

**同种子 + 同 tick 数 ⇒ 逐字节相同的世界。**

这不是洁癖，而是三项功能的先决条件：

1. **存档能原样复现** —— 一个演化了几十万 tick 的生态箱，存下来再打开必须一模一样。
2. **实验可对照** —— 改一个参数、跑两次，差异必须来自参数而不是随机。
3. **Bug 可复现** —— 否则"第 37 代出现了奇怪行为"这类问题无从查起。

实现要点：

- 自己写 **xorshift128+**，不用 `System.Random`（它不保证跨版本序列稳定）。
- 噪声传感器用 `Hash(个体Id, tick)` 而不是 RNG（见第 2 节的坑）。
- 遍历顺序、tick 内各阶段顺序固定；攻击者顺序用 `Tick % N` 轮转偏移消除系统偏差。
- 浮点运算全部 `float` 且顺序固定。

**验证方式**（已通过）：同种子跑两次，导出的种群曲线 CSV 与冠军基因组 JSON
**哈希完全一致**。

```powershell
Terrarium.Headless --ticks 30000 --every 2000 --csv a.csv --export g.json
Terrarium.Headless --ticks 30000 --every 2000 --csv b.csv --export h.json
# a.csv == b.csv 且 g.json == h.json
```

## 9. 规则编辑器：为什么是卡片而不是积木

**卡片式 = 一组下拉框 + 数字输入框，按优先级从上往下排。**

理由很实在：像素级积木拖拽（拖拽、吸附、嵌套、滚动、撤销）的工程量能占整个项目的 60%，
而**表达能力并不比卡片式强** —— 两者都是"条件 AND + 动作列表 + 优先级排序"。

卡片式的额外好处：

- 数字输入框天然适合"改一个阈值跑一次看结果"这种实验性玩法。
- 无障碍、可键盘操作、高 DPI 下不会错位。
- 后续想加积木视图，可以作为**皮肤**叠加在这一层之上，而不必重写数据模型。

编辑器的工程约定：

- 始终操作一份**基因组副本**，只有按下「保存到选中」才写回生物 ——
  边跑模拟边改规则不会互相打架。
- 保存时会立刻 `RecalcDerived()`，否则玩家会看到"改了器官但速度没变"的鬼影。
- 「投放一只到生态箱」把编辑结果变成真实个体，它之后会像其他生物一样突变和繁殖。

### 渲染策略（性能的关键）

- **地形 + 食物层先画进一张 `TileW×TileH` 的小位图**（用 `LockBits` 直接写像素），
  再整张拉伸贴上去 —— 而不是画 5400 个矩形。这一步是从"卡"到"流畅"的分界。
- **生物只画身体 + 朝向三角**，描边颜色表示生命值、明度表示能量（一眼看出谁快饿死）。
- **器官部件只在放大到足够尺寸时才画**（视野半径 ≥ 1.1 px/单位），
  避免几百个 GDI+ 调用拖慢帧率。
- 昼夜光照整体压暗，但下限保持在 62% —— 否则一到夜晚整个生态箱黑成一片。

### 选中一只生物能看到什么

这是整个程序最有教育意义的部分：**它此刻感知到的每一个数字、以及它正在执行哪一条规则。**
比如"最近敌人距离 0.81、我的能量% 0.35 → 执行第 3 条：攻击最近敌人"。
你会亲眼看到一条蠢规则怎么在几十代之后变成一个有效的狩猎策略。

### 一处踩坑记录

WinForms 的 `SplitContainer` 有两个静默陷阱，都造成了"面板整个不见了"：

1. **构造期设 `SplitterDistance`** —— 那时容器宽度还是默认值，
   会被静默钳到边界值。必须在窗口有真实尺寸之后再设。
2. **构造期设 `Panel1MinSize` / `Panel2MinSize`** —— 两者之和超过容器当前宽度时，
   `SplitContainer` 会直接抛异常把程序干掉。

还有一个更隐蔽的：**`Form` 在构造函数里设置 `MinimumSize` 就会触发 `OnResize`**，
而那一刻 SplitContainer 字段还是 `null`。必须用一个 `_layoutReady` 标志挡住。

## 11. 实测到的演化现象

以下都是真实跑出来的，不是设计意图。复现命令在括号里。

### 11.1 突变率的自发下降（元演化）

初始 0.35，12 万 tick 后稳定在 **0.13–0.29**。
稳定环境里的保守化 —— 因为高突变率的个体更容易生出坏后代。

### 11.2 规则复杂度的先增后稳

5 条 → 13.6 条（无规则维持成本时）→ 加上成本后稳定在 **5–9 条**。
说明"神经系统开销"确实是控制基因组膨胀的有效闸门。

### 11.3 器官特化（多物种共存）

```
物种 #3   701 个体   器官 腿2.0 眼2.0 牙2.0 胃1.0   平均体重 4.35   ← 掠食者赢了
物种 #2    56 个体   器官 腿3.0 眼2.0 胃0.9         平均体重 3.43   ← 疾行者残存
物种 #8     8 个体   器官 腿2.0 眼2.0 牙1.2 胃1.8 鳃0.8           ← 水生掠食者
物种 #1     2 个体   （食草者，濒临灭绝）
```

`--repeat 5 --ticks 60000 --water 0.18`

### 11.4 捕食的涌现与捕食者-猎物周期

6 万 tick 内 **11239–24169 次猎杀**（约每秒 4–8 次），
种群在 100–700 之间震荡。这是真实的 Lotka-Volterra 式振荡。

### 11.5 体型的两条演化路径

- 食物充裕时 → 体型一路增大（4.40 → 5.9），因为大就是强。
- 食物成为限制后 → **体重反向下降**（4.40 → 2.03），战力从 0.61 掉到 0.13。
  生物学会"躺平省钱"，这本身就是一次完整的 r/K 选择实证。

### 11.6 种群瓶颈会砍掉深代谱系

一次崩溃（340 → 95）让最深代数从 22 停滞了 6000 tick，
而**平均代数一直在涨**（12.8 → 27.3）。
只看 max 会误以为演化停了 —— 这也是为什么统计里同时输出 max 和 avg。

## 12. 调参手册（含失败结论）

### 最敏感的旋钮

| 参数 | 默认 | 调高的后果 | 调低的后果 |
|---|---|---|---|
| `FoodRegen` | 0.0022 | 食物过剩，生物变大变和平 | 濒临灭绝 |
| `BaseUpkeep` | 0.010 | 全世界变艰难，种群变小 | 种群爆炸到上限 |
| `Lifespan` | 3600 | 老个体占资源，**演化变慢** | 世代更替快，演化快 |
| `AttackLungeMultiplier` | 2.0 | 捕食凶猛，猎物可能被吃绝 | **< 1.0 时捕食彻底消失** |
| `PredationFlatBonus` | 18 | 捕食者指数爆炸然后饿死 | 没人愿意当捕食者 |
| `RuleUpkeep` | 0.0030 | 行为变简单 | 基因组膨胀成垃圾堆 |
| `OrganTable.UpkeepExponent` | 1.65 | 极端特化，物种多 | 全场全能型，无生态位 |
| `WaterFraction` | 0.18 | 水域生态位变强 | 长期塌缩成单一物种 |

### 失败结论（省得你再试一遍）

1. **降低肥沃地块占比 ≠ 加强竞争。**
   直觉上"食物集中 → 竞争激烈 → 捕食有利"，实测恰恰相反：
   `FertileFraction` 0.55 的捕食次数是 0.22 的 **3–4 倍**。
   因为**种群密度本身才是竞争强度的主要来源**，食物一少种群先崩，
   什么都没了。别凭直觉调它。

2. **`FertileFraction` 0.22 会让种群崩到个位数。** 见上。

3. **捕食收益给太多会系统崩溃。**
   `PredationFlatBonus` 曾设 25，捕食者在 1 万 tick 内制造 12343 次猎杀，
   然后猎物崩盘、捕食者跟着饿死，种群在 777 → 102 → 514 → 105 之间剧烈震荡。

4. **规则维持成本给太少等于没给。**
   0.0016/tick 时规则数照样涨到 10.6 条（只占总开销 11%）。
   提到 0.0030 才开始真正起约束作用。

5. **无头跑得比想象中慢。**
   单线程 800 个体约 1300–2800 tick/s。跑 10 万 tick 要 1 分钟左右。
   大世界 + 高视野 = 平方级增长的环扫描开销，这是主要瓶颈。

## 15. MVP-2 的实现细节与踩坑

### 15.1 为什么"没区分"其实是三个问题

玩家反馈是"不同物种之间还是没有区分，外观和体型上没有差距"。查代码发现是三件事叠在一起：

**① 器官在默认视角下压根不画（最直接的原因）**

```
世界 1800×1200，画布 971×585
FitScale = min(971/1800, 585/1200) × 0.97 = 0.473
生物半径 = (3.6 + 体重×1.25) × 0.473
体重 3.9 → 半径 4.0 px → 直径 8 像素
```

而器官部件的绘制阈值是 `缩放 ≥ 1.1` —— 默认缩放只有阈值的 43%。
**信息一直都在**（实测体重跨度 1.33–6.12，差 4.6 倍），只是根本没被画出来。
所以第一优先级是渲染尺度，不是生态。

**② 物种是随机贴的标签**，`SpeciesId` 由每次繁殖 2.2% 的随机概率生成，与基因差异无关。
后果：物种数是随机噪声、同物种可能基因差很远、捕食者在打自己的镜像。

**③ 世界是均质的**，没有屏障就没有地理隔离，竞争排斥必然收敛到单一物种。

修法分别对应：渲染重做 / 物种重定义（未做）/ 地形系统（已做）。

### 15.2 身体形状：让器官在轮廓上留下痕迹

以前所有生物都画成同一个圆。现在身体是一个按器官构成变形的多边形：

```
腿   → 沿朝向拉长（流线型）        甲   → 侧向压平成多面体
牙   → 前端推出成楔形              藻胞 → 表面隆起成不规则团块
胃   → 整体圆润                    棘   → 轮廓外凸成星形
```

再叠一个由个体 Id 派生的**稳定哈希噪声**，于是同物种的个体也不会长得一模一样，
而且同一个体每帧形状一致（不会抖）。

**三级 LOD 按屏幕半径切换，而不是按缩放倍数** —— 真正决定"看不看得清"的是它在屏幕上有多大：

| LOD | 触发条件 | 内容 |
|---|---|---|
| 0 | 总是 | 身体多边形 + 生命描边 + 能量明度 |
| 1 | 半径 ≥ 3.2 px | 牙、甲环、棘刺、腿 |
| 2 | 半径 ≥ 8 px | 眼、藻胞、毒腺、鳃 |

### 15.3 物种配色：不用那个会漂移的色相基因

原先用基因组里独立变异的 `Hue`，结果同物种颜色散开、不同物种撞色。
改成按物种序号用**黄金角**（0.6180339887）展开色相：相邻序号在色环上尽可能远离，
而且只要物种 Id 不变颜色就永远稳定。

### 15.4 地形系统

| 地形 | 通行 | 移动代价 | 食物容量 | 视野 |
|---|---|---|---|---|
| 草地 | ✓ | 1.00 | 0.35 | 1.0 |
| 沃土 | ✓ | 1.00 | 0.95 | 1.0 |
| 灌木丛 | ✓ | 1.60 | 0.55 | **0.5** |
| 浅水 | ✓ | 1.30 | 0.70 | 1.0 |
| 深水 | 仅带鳃 | 1.00 | 0.85 | 1.0 |
| 沼泽 | ✓ | 1.90 | 0.50 | 0.7 |
| **岩石** | **✗** | — | 0 | — |
| 荒漠 | ✓ | 1.05 | 0.06 | 1.0 |

**浅水可涉水、只有深水会溺**：这个梯度很关键 —— 浅水是走廊，深水才是屏障。
全是屏障的水域只是一个惩罚区，不是栖息地。

**灌木丛砍半视野**：不需要真正的视线遮挡计算，只是把有效视野乘一个系数，
却凭空造出"伏击"和"藏身"两个战术生态位。

生成方式：高程 fBm 决定山脉与湖泊，湿度 fBm 决定植被带，
所有阈值按**目标占比取分位数**，所以"水域占比 / 山地占比"是精确可控的。

### 15.5 逃逸距离场：不做逐个体 A* 也能不卡死

岩石不可通行必然带来"卡在凹角里"的问题。逐个体每 tick 跑 A* 在 2000 个体下完全不可行。

解法：从所有可通行地块出发做**一次多源 BFS**，得到每个地块"往哪走能出去"的方向与步数。
预计算 O(地块数) = 16000 步，之后每个生物每 tick 只是查一次表。
地形改动时才重算（而且是在**笔画结束时**统一重算，不是每帧）。

配套加了 `前方障碍距离`、`被围困程度` 两个传感器，
于是一条「当 前方障碍距离 < 0.3 → 转向 随机方向」的规则就能让演化自己解决避障。

### 15.6 碰撞体积

身体有半径，重叠时按体重反比推开（重的推不动），每 tick 只推 50% 并设位移上限，
等价于一次 Gauss-Seidel 松弛 —— 天然收敛且不需要去重。

拥挤还要花能量（`CrowdCost`）。这让"扎堆"有真实的代谢代价，
群居和分散都成为需要权衡的策略，而不是单纯的人多力量大。

空间哈希格子必须 ≥ 最大体径的 2 倍（改成 72），否则 3×3 邻域会漏掉重叠对。

### 15.7 性能：并行感知-决策带来 2.1 倍

**这是整个项目里最容易拿到、也最安全的性能收益**，因为它不改变任何行为。

tick 主循环被切成两个阶段：

```
阶段一：感知 + 决策（可并行）
  Sense 只读世界状态，Think 只读基因组，唯一写操作是写自己那只生物的
  LastRule/Intent 字段。按个体切开并行跑，结果与串行完全一致 —— 确定性不破。
  这是最热的一段（环扫描全在这里）。

阶段二：执行（必须串行）
  动作会修改位置、食物存量、生老病死，全是有副作用的。
```

实测：**363 → 765 tick/s（2.1×）**，同种子输出仍逐字节一致。
2.1× 而不是 8×，是因为执行 / 代谢 / 碰撞 / 食物再生仍是串行（Amdahl 上限 ≈ 2.1）。

**一个差点被骗的教训**：A/B 测出"关闭碰撞体积快 36%"，看起来碰撞很贵。
但并行化之后重测，关掉碰撞反而更慢 —— 因为两次运行的**人口根本不同**，
差异来自生态而不是代码。**做 A/B 性能测试时必须同时看人口**，否则结论完全是假的。

### 15.8 地形编辑器的三个设计决定

1. **一次拖拽 = 一笔 = 一次撤销单位**。撤销用"地块差异栈"而不是整图快照：
   一笔可能只改 200 个地块，存整张图（上万个 float）纯属浪费。
2. **逃逸距离场在笔画结束时才重算**，不是每帧。拖拽过程中每帧跑一次 16000 步 BFS 是纯浪费。
3. **编辑模式下点击不再选中生物** —— 否则画地形时会不断误触选中。

验证方式（已通过）：脚本模拟真实鼠标拖拽，比对绘制前后区域平均色（绿通道 +89），
再点撤销确认完全还原（回到原值 ±6 以内）。

### 15.9 生态上踩到的两个失控

**① 繁殖阈值高于能量上限 → 出生数为 0。**（MVP-1 时期）
第一版阈值 110、创始生物能量上限 88，结果 6400 tick 里出生数 0，所有初代同时寿终直接灭绝。

**② 按体重的捕食奖励会形成"越大越吃"的正反馈。**
`PredationFlatBonus × 猎物体重` 在体重 21 时一次击杀给 378 能量 ——
足够维持 470 tick 的开销。于是演化出"全器官点满"的巨型生物（体重 17–21、战力 1.00），
靠同类相食自持，完全脱离植物食物链，种群在 777 → 102 → 514 → 105 之间剧烈震荡。

修法是三处联动：器官开销指数 1.65 → 1.90、基础代谢对体重改成超线性（`mass^1.35`）、
捕食奖励改成 `√体重`。改完之后体重收敛到 3.5–11，生态系统重新由植物食物链主导。

## 16. 捕食者 / 食草者体系：一次彻底的重做

玩家反馈："捕食者、食草者的体系设计得十分糟糕，它们几乎会很快只剩下掠食者这一个。"
**这个判断完全正确，而且它不是观感问题，是设计缺陷。**

### 16.1 症状

| 指标 | 修复前 |
|---|---|
| 战力（6 个种子） | 0.90 / 0.91 / 0.45 / 0.92 / 0.90 / 0.90 |
| 平均牙等级 | 2.2 – 4.0 |
| 6 万–4.5 万 tick 内的猎杀数 | 66,387 – 296,214 |
| 食性宽容度（可演化） | 0.65 – 0.96（趋近"谁都能吃"） |

不是"掠食者强势"，是**每一个个体都在吃每一个个体**的绞肉机。食草生态位根本不存在。

### 16.2 根因：我把能量守恒破坏了

```csharp
// 修复前
float gain = target.Energy * 0.70f + MathF.Sqrt(target.Mass) * 18f;
//                                               ^^^^^^^^^^^^^^^^^^ 凭空造能量
```

体重 5 的猎物，一次击杀送 40 能量。而**植物全图每秒只产约 92 能量**。
按 6.6 次/秒的击杀频率，捕食每秒往系统里注入 **263 能量 —— 是植物总产量的 3 倍**。

于是"多杀"永远是压倒性最优解，任何不捕食的个体都被淘汰。这跟变异算子、规则设计
统统无关，就是一个算术错误。

我当初加这一项的理由是"猎物身上那点余粮不值一条命，真正值钱的是它这具身体本身"。
理由本身不算错，**但实现方式违反了守恒律** —— 应该从猎物已有的能量里扣，而不是凭空生成。

### 16.3 四处结构性修改

**① 捕食回归能量转移。**
`伤害收益 = 猎物能量 × 0.55 + √猎物体重 × 4`。第二项是唯一的净注入，压到很小。
效果立竿见影：猎杀数降 10–50 倍，掠食者占比从"恒定 90%+"变成 **2%–72% 的震荡**
（真实的捕食者-猎物周期），食性宽容度也第一次出现了反向压力（掉到 0.05–0.68）。

**② 营养级效率。** 真实食物链每一级要损失约 90% 的能量，这是顶级捕食者稀少的原因。
`PredationGain` 从 0.8 降到 0.55，捕食变成"快速拿到一顿饭"而不是"高效获取能量"。

**③ 器官的零级基线必须很差。**
这是另一个独立的结构缺陷：第一版里"不带任何器官"的生物是**完全可用**的 ——
视野 45、速度 1.0、能量上限 70。于是"什么都不长"成了免费的最优解，
演化一路退化成体重 1.18、只剩 眼0.5 的极简生物，世界变成一个毫无区分的单质。

改成：

| 属性 | 零级 | 五级 |
|---|---|---|
| 视野 | 14（近似全盲） | 244 |
| 速度基数 | 0.40（几乎挪不动） | 5.15 |
| 能量上限 | 28（一次进食就撑爆） | 128 |
| 咬合速率 | 0.15（吃得极慢） | 0.53 |

把零级压到几乎不可用之后，演化**必须**投资器官，而器官开销是超线性的 ——
于是"要什么"才成了真正的取舍，这才谈得上生态位。

**④ 器官在指纹里的权重提高 6 倍。**
第一版所有维度等权，10 个器官维度淹没在 117 维里 ——
"牙差 2 级"这种肉眼可见的形态差异对指纹距离的贡献只有 0.34%，
于是物种判定实际上判的是行为而不是身体，形态差异巨大的捕食型与植食型被算成同一物种。
器官是玩家看得见的东西，也是生态位分化的主轴，理应主导物种判定。

### 16.4 修复后的结果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 存活物种数 | 1（随机标签） | **7 – 110** |
| 战力 | 0.90–0.94 全场最高 | **0.36 – 0.99，按种子分化** |
| 6 万 tick 猎杀数 | 66,387 – 296,214 | **18,118 – 39,260** |
| 存活率 | 6/6 | 6/6 |

器官构成从"清一色牙 2–4"变成了真正不同的生存方案：

```
腿3.0 眼2.0 胃2.0 生殖腺1.0              植食 + 高繁殖
腿2.0 眼2.1 胃3.0 藻胞1.0                光合自养 + 大胃
腿4.9 眼2.0 牙2.0 甲0.7 胃3.4            重甲掠食者
腿4.9 眼1.0 牙3.0 胃3.0 毒腺1.0          高速毒腺掠食者
```

### 16.5 物种分化阈值：从绝对值改成自动校准

第一版用绝对阈值 0.055，结果 6 万 tick 里裂出 **28,597 个物种** ——
几乎每次繁殖都算新种，"物种"彻底失去意义。

改成以**突变步长**为单位的倍数之后，阈值会自动跟着变异强度、规则数、世界参数一起缩放。
校准量必须是"父代 vs 子代的指纹距离"，**不能**用"子代 vs 物种中心"：
后者会随物种年龄单调增长，于是阈值跟着涨、分化越来越难，最后锁死在单一物种上
（实测过：只剩 1 个物种）。

实测的取舍：

| 倍数 | 存活物种 | 物种差异 | 猎杀数 | 掠食者占比 |
|---|---|---|---|---|
| 2 | 113 | 0.155 | 128,677 | 75%（绞肉机回归） |
| **3.5** | **7–110** | **0.081** | **18,118** | **分化** |
| 25 | 1–2 | 0 | 829 | 0% |

### 16.6 三个测试方法上的教训

**① A/B 性能测试必须同时看人口。**
曾测出"关闭碰撞体积快 36%"，并行化之后重测却发现关掉碰撞反而更慢 ——
因为两次运行的**人口根本不同**，差异来自生态而不是代码。结论完全是假的。

**② 命令行默认值会静默覆盖配置类默认值。**
无头台的 `CliOptions.SpeciationFactor` 默认是 25，而 `BuildConfig` 每次都把它写进
`SimConfig`。于是我改了半天 `SimConfig` 的默认值，`--repeat` 测的一直是 25，
几次"验证"结果一模一样却没察觉。**测试脚手架本身也需要被验证。**

**③ 不要把"看起来对"的指标当目标。**
`战力`（牙 + 棘 + 体重）一度被当成"掠食者强势"的证据，但它把所有形态差异都糊成了
一个数。真正该看的是**牙 ≥ 2 的个体占比**（掠食者占比）和**猎杀/出生比**。
换了指标之后，问题一眼可见。

### 16.7 仍然没解决的问题

**长期来看，共存物种仍会收敛到 1–3 个优势种。**

这是竞争排斥原理的必然结果：环境里只有一个限制性资源（植物），
而所有策略都能用同一种方式去利用它 —— 没有"硬取舍"。
真实生态系统靠的是多个限制因子、频率依赖选择和合适尺度的空间异质性。

我们已经有空间结构（8 种地形、7% 岩石），但它**没能**维持多样性，因为：
- 腿和眼在所有地形上都有效，没有"水域专家在陆地上必然劣势"这种硬约束
- 鳃很便宜（0.007/级），只有 10% 的深水需要它，所以通才几乎不受限制

要真正解决，需要**互相排斥的取舍**（比如鳍与腿互斥、沙漠需要耐热因而不能同时重甲），
那是一次更大的生态重设计，不是调参能到的。这一条我在路线图里明确标出来了。

## 17. 局部 A* 寻路：怎么做到"能绕障"又不吃光算力

### 17.1 问题

岩石不可通行之后必然出现"生物撞在岩壁上卡住"。
3200×2000 的世界有 16000 个地块，而生物可能有几千个 ——
**每个生物每 tick 跑一次完整 A\* 会直接吃光全部算力**，这是这类模拟里最常见的性能陷阱。

### 17.2 三道闸门，按"越靠前越便宜"排序

```
1. 免费闸门   —— 复用感知阶段已经算好的「前方障碍距离」传感器。
                 它等于 1（前方 90 单位畅通）就整段跳过。
2. 直线可视性 —— 沿直线采样查表判断有没有被岩石挡住。
                 绝大多数请求在这里被拒掉，根本不进 A*。
3. 全局预算   —— 每 tick 调用次数上限 + 全局节点展开上限。
                 保证寻路总开销有硬上限，与生物数量无关。
```

第三道闸门里，**节点预算是必须单独加的**：只限"调用次数"是不够的，
单次最坏几百个节点，在几千生物的场景下仍能把一帧打爆。

### 17.3 关键优化：跟随整段路径，而不是只返回下一步

第一版只返回"下一步该往哪走"。结果实测寻路吃掉 **26%** 的算力 ——
因为路点只有约 1.2 格远，生物每走一格（约 15 tick）就要重算一次 A*。

改成一次返回整段路径（最多 8 个路点）并跟着走之后：

| 指标 | 只返回下一步 | 跟随整段路径 |
|---|---|---|
| A\* 调用次数（4 万 tick） | 677,972 | **299,018** |
| 展开节点数 | 9,993 万 | **4,987 万** |
| 性能开销 | 约 26% | **约 6%** |

### 17.4 实测效果

寻路不只是"不卡死"，它实实在在改变了生态：

| 指标（6 万 tick） | 无寻路 | 有寻路 |
|---|---|---|
| 人口 | 517 | **638** |
| 平均能量 | 44.1% | **49.8%** |
| 猎杀数 | 18,118 | **8,578** |

人口和能量都更高 —— 觅食效率提升了；猎杀数更低 —— 猎物能绕开障碍逃走。

### 17.5 若干实现细节

- **对角穿越要检查两侧**，否则生物会从两块岩石的夹角"挤"过去。
- **用时间戳数组代替每次清零**（`_stamp[i] == _stampCounter`），
  否则每次搜索清 16000 个 float 的开销会超过搜索本身。
- **搜索状态全部复用**，整个 PathFinder 是零分配的 —— 放在热路径上不给 GC 添麻烦。
- **地形改动后必须作废所有生物的缓存路径**，否则它们会沿着已经不存在的路走。

## 18. 地图存档

### 18.1 为什么必须能存

地形编辑器让玩家可以手绘地貌。如果这些不能保存，
所有手工劳动在关掉程序的一瞬间就没了，编辑器也就失去了意义。

### 18.2 格式

**JSON（人可读的元数据）+ 三个 gzip+base64 的二进制块（大数组）。**

- 存：地形、肥力、食物存量，以及影响地形生成的那几个配置
  （水域/山地/森林/荒漠/沼泽/肥沃占比、水生富饶度）。
- **不存生物**：本项目是确定性的，"地图 + 种子"就能精确重放整个演化史。
  存下来只会让文件变大，而且容易和版本脱节。

实测：16000 地块的完整地图 **151.8 KB**。
（比预期大 —— 因为地形是噪声生成的，而噪声几乎不可压缩。）

### 18.3 自动化验证

地图存档这条链路横跨：手绘改动 → 打包 → gzip → base64 → 写文件 → 读文件 →
解包 → 装回 World → 重算逃逸距离场 → 刷新缓存版本号。
**任何一环错了，界面上都只表现为"载入之后地形没变"或者"变了一半"。**

所以加了 `--maptest` 自检：

```
存原始地图 → 涂抹 3292 个地块变成岩石 → 载入回来 → 逐字节比对

地形不一致地块 : 0 / 16000
肥力不一致地块 : 0 / 16000
逃逸场已重算   : True
```

## 20. 点数预算：把"我是谁"变成一道必须回答的题

### 20.1 为什么要有硬上限

第一版靠**超线性开销**（等级^1.9）压制"什么都点满"。那是个经济补丁 ——
只要食物够多，全场还是会长成一模一样的全能型（实测过一次：体重 21、全器官 3–5、战力 1.00）。

**20 点硬上限是从结构上禁止这件事**：15 个性状里最多只能点满 4 个，剩下的必须保持低等级。
不再需要经济手段去"劝"生物特化，因为物理上它就做不到全能。

### 20.2 完整性状表（15 项共享 20 点）

| 器官（10） | 效果 |
|---|---|
| 腿 / 眼 / 牙 / 甲 / 胃 | 移速 / 视野 / 攻击 / 减伤 / 能量上限与消化 |
| 藻胞 / 毒腺 / 生殖腺 / 鳃 / 棘 | 光合 / 中毒 / 繁殖门槛 / 水域 / 反伤 |

| 生活史（5） | 效果 | 以前的状态 |
|---|---|---|
| **寿命** | 自然寿命上限 | 全局写死 3600，**不可演化** |
| **繁殖间隔** | 两次产卵的冷却 | 全局写死 80，**不可演化** |
| **幼体生命力** | 幼体属性保留比例 + 成熟速度 | 不存在 |
| **窝卵数** | 一次产几颗卵 | 不存在 |
| **卵壳强度** | 卵能扛几次非同族踩踏 | 不存在 |

「生殖腺」和「繁殖间隔」**不重复**，是两个轴：前者是**门槛**（攒够多少能量能生），
后者是**冷却**（生完要等多久）。

### 20.3 突变算子：转移 + 净增

```
转移：从性状 A 扣 1 点，加到性状 B 上（总数不变）
净增：给某个性状 +1（前提是总数 < 预算）
净减：扣 1 点（总数下降，个体变便宜）
```

**转移这一条是必须的。** 如果只有净增/净减，那么点数用满之后净增被彻底堵死，
演化会僵在第一个"用满点数"的局部最优上。有了转移，生物可以在总量不变的前提下
不断重新分配 —— 这才是"特化方向"能被持续搜索的前提。

### 20.4 实测：上限守住了，但生物选择"用不满"

6 万 tick 的跑动里，平均已用点数 **12.6 – 13.6**（上限 20）。

也就是说：**约束是硬的，但生态最优解在约束之下**。
用不满的生物更轻、每 tick 开销更低 —— 这正是"躺平省钱"从隐性行为变成明牌的结果。
调 `PointUpkeep`（单点开销）就能移动这个平衡点。

## 21. 卵生与幼体：生命周期第一次有了阶段

### 21.1 生命周期

```
成体（能量 ≥ 门槛  且  产卵冷却已过）
   │  【产卵】
   ▼
卵 × 窝卵数（散落在亲代周围）
   │  孵化计时（可被亲代「孵卵」加速）
   ▼
幼体（属性按成熟度缩放，不能繁殖）
   │  成长
   ▼
成体
```

### 21.2 卵的销毁机制：踩踏，不是血量

**被非同族踩 5 次就直接销毁**（这个数字不是全局配置，是「卵壳强度」买来的：
0 级 1 次，每级 +2，2 级正好 5 次）。

为什么不用血量：卵不会反击，也不需要被"战斗"，它只是挡在路上了。
踩踏比"攻击掉血"更贴合这个意象，而且它让**移动本身**成为一件有后果的事 ——
一群生物踩过去，卵就没了。

两个必要的细节：
- **同族不踩**。判定用卵记录下来的**亲代签名**，因为亲代很可能在孵化前就死了，
  但敌友判定不能因此失效。
- **两次踩踏之间有最小间隔**（18 tick）。没有它，一只生物站在卵上就能一 tick 踩满次数。

### 21.3 一个真实后果：卵是生态里第一种"不用搏斗就能吃"的资源

这直接开出两个新生态位，而且都不需要专门写代码，只是规则组合：

```
当 最近的敌方卵距离 ≤ 0.45 且 我的生命% > 0.55 → 吃卵 → 最近的敌方卵
当 最近的友方卵距离 ≤ 0.55                    → 孵卵 + 攻击最近的敌人
```

于是「抢劫」和「护卵」成了真实策略。实测 6 万 tick：孵化 11821 次、被踩碎 2585 颗
（约 18%），猎杀 5053 次 —— 抢劫卵确实分担了一部分觅食压力。

### 21.4 幼体

| 项目 | 实现 |
|---|---|
| 属性缩放 | 体径 / 血量 / 攻击按成熟度在「幼体基线」与 1.0 之间插值 |
| 幼体基线 | `0.25 + 幼体生命力 × 0.09`（0 级 0.25，5 级 0.70） |
| 代谢 | 幼体开销 × 0.65，随成熟度恢复全额 |
| 繁殖 | 不能（可配置） |
| 画面 | 更小、更淡 —— 生命阶段必须一眼可辨 |

实测幼体占比长期在 **51%–66%**，说明"成长"确实是种群里的主要状态，而不是一个装饰。

### 21.5 一个差点毁掉演化的 bug

第一版的 `HatchEgg` 是拿**物种模式标本**临时重建基因组的（当时担心每颗卵存一份基因组太占内存）。
后果：**每一只孵出来的个体都退回祖先**。

实测症状非常隐蔽 —— 种群、卵数、孵化数全都正常，只有三个数字不对：

```
代数max = 0        （永远是 0）
突变率  = 0.350    （恒定在原型值）
点数    = 14.0     （恒定不动）
```

**演化信号被完全抹掉了，但表面上一切正常。** 修法是让卵直接持有子代基因组的引用
（同一窝共享一份，所以内存是"每窝一份"而不是"每颗一份"）。
修完之后代数到 22、突变率开始漂移、点数开始变化。

教训：**当所有"总量"指标都正常、只有"演化"指标不动时，先去查新生个体的基因组是从哪来的。**

## 22. 移植到 Android：内核一行没改，界面全部重写

结论先说：这件事之所以做得成，是因为**当初把模拟内核和界面彻底分开了**。

`Terrarium.Core` 5470 行，零 Windows 依赖、零 UI 依赖，只依赖 `System.*`。
从 WinForms 搬到 Android，它的 target framework 从 `net9.0-windows` 换成 `net9.0`，
**其余一个字节都没动**。重写的是 `Terrarium.App` 那 3473 行 GDI+ 代码。

这不是运气，是那条规则的回本：*模拟内核不许知道任何关于窗口的事。*
如果当初让 `World` 持有一个 `Graphics` 或者直接读 `Control` 的尺寸，
这次移植的工作量会从"重写界面"变成"重写全部"。

### 22.1 平台无关的那部分

| 内核里的东西 | Android 上直接用 |
|---|---|
| `Simulation` 门面 + `Snapshot()` | ✅ 快照机制天然适合"后台算、前台画" |
| 8 种地形 / 逃逸距离场 / A* 寻路 | ✅ |
| 基因组 / 规则 / 变异 / 物种指纹 | ✅ |
| 卵 / 幼体 / 成熟度 | ✅ |
| `SpeciesPalette.HueFor()` | ✅ 黄金角配色搬过来就是对的 |
| `Parallel.For` 感知-决策 | ✅ Mono 上有线程池，行为一致 |

### 22.2 必须重写的那部分

GDI+ 的 `Graphics` 和 Android 的 `Canvas` 是两套完全不同的 API，没有适配层可写。
但**渲染的算法本身是平台无关的**，可以逐行搬：

- **身体轮廓**：`BuildBodyPolygon` 从器官等级推形状（腿拉长、甲压扁、牙出楔、胃发圆、
  藻胞起包、棘长刺），配一个由个体 id 决定的稳定哈希做外形微扰。
  这段数学在桌面版和 Android 版里是同一份，因为它是纯函数。
- **最近邻放大**：桌面版早就发现地形位图只有 160×100，放大六倍用双线性会糊成一片。
  Android 上同理，用 `Bitmap.FilterBitmap = false`。
  *这个问题在两个平台上长得一模一样，因为它是缩放倍率的问题，不是平台的问题。*
- **领地叠加**：alpha `min(8 + 个体数*3, 30)`。

真正新的只有**输入**：鼠标换成触摸。多出三件桌面版没有的事：

- **手指比鼠标粗**：选取判定半径从 10 像素放宽到 34 像素，否则点不中。
- **双指缩放要以手指焦点为中心**，不能以屏幕中心 —— 否则想放大某个角落时它会跑掉。
- **单指既要拖动又要点击**：靠抬起时的位移阈值（14 像素）区分，不是靠按下时长。
  用时长区分在快速点击时会误判成拖动。

### 22.3 手机上是故意"少"的

规则编辑器、地形编辑器、群系生成、物种差异矩阵、环境滑块 —— 全部**没有**移植。

它们都是"改规则"的工具，功能上没问题，问题是**在 6 吋屏幕上做不了**：
规则卡片编辑需要同时看到条件、动作、参数和一个完整列表，
这不是把字号调小就能解决的，是布局范式不匹配。

所以 Android 版的定位是**观察器**：看世界怎么演化、点开一只生物看它在想什么。
想改规则就回桌面版改，改完的地图能存档，理论上可以传过去 —— 但生物不存，
所以"地图 + 种子"是唯一能跨平台重放的东西。（这一条也解释了 `MapIO` 为什么不存生物。）

### 22.4 性能上的两个让步

- **倍速上限砍到 60 tick/s，且没有"不限速"档。**
  桌面版有不限速（跑满一个核心）。手机上那样跑会**发烫 + 掉电**，
  而且小屏幕上 tick 跑到几千你也看不出区别。
- **模拟线程优先级 `BelowNormal`。**
  手机上模拟绝不能和 UI 抢 CPU —— 抢输了是掉帧，抢赢了是 UI 卡死然后被系统判定无响应。

还有一条沿用桌面版的坑：**倍速累加器必须是 `double`。**
用 `int` 时每帧 `(1 tick 的量)` 被截断成 0，模拟会彻底停住而 UI 看起来完全正常。

### 22.5 这次移植没能验证的部分

必须写明：**这个 APK 没有在任何真机或模拟器上运行过。**

构建它的机器 CPU 不支持虚拟化（Xeon E3-1230 V2，BIOS 里 VT-x 没开），
`HypervisorPresent` 和 `VirtualizationFirmwareEnabled` 都是 `False`，
Android 模拟器没有硬件加速就慢到无法启动；也没有接真机（`adb devices` 是空的）。

所以验证只到"编译期 + 结构"这一层：编译 0 警告 0 错误、
`aapt2 dump badging` 清单合法、APK 里 Mono 运行时和两个 ABI 的 AOT 产物都在、已签名。
**渲染正确性和触摸手感没有被验证过** —— 这是这份代码里唯一一块没底的地方。

应对方式是给三条最容易"死得不明不白"的路径都包了兜底，出错时**把原因直接显示在屏幕上**：

| 死在哪儿 | 默认表现 | 兜底后的表现 |
|---|---|---|
| `MainActivity.OnCreate` 建世界 | 点开图标，闪一下就没了 | 全屏 TextView 显示异常 |
| `TerrariumView.OnDraw` 渲染 | 一片黑屏 | 异常类型 + 消息 + 堆栈画在屏幕上 |
| 后台模拟线程 | **整个进程被杀**（Android 上后台线程未捕获异常 = 进程死亡） | 停循环 + 屏幕显示"模拟线程已停止" |

第三条最要紧：后台线程的异常在 Android 上不是"那条线程退出"，是**整个应用的进程被干掉**，
用户看到的是"玩着玩着应用自己没了"，除了重开别无办法，也完全无从反馈。

这不能替代测试，但能把"装上去一片黑 / 莫名其妙闪退"变成一条可读的错误信息。

### 22.6 代价

构建机磁盘少了 **5.4 GB**（Android SDK 395 MB + JDK 17 301 MB + .NET Android packs 约 3 GB
+ 构建产物与 NuGet 缓存），系统盘一点没动（反而多出 0.5 GB）。
比事先估的 2 GB 多了一倍多 —— **Android 工具链比想象中重**，
`Microsoft.Android.Sdk` 加上四个 ABI 的 Mono 运行时和 AOT 交叉编译器，
光 packs 就有 3 GB。这部分只在**重新构建**时需要，产物本身只有 7.94 MB。

另一个硬约束值得记下来：**.NET Android 35 不认 JDK 21，只认 JDK 17**（`XA0030`）。
系统里装的是 JDK 21，所以另备了一份 JDK 17 单独指给 `JavaSdkDirectory`。
把 `JavaSdkDirectory` 指到 JDK 21 上还会连带触发
`XARAT7001: System.NullReferenceException ... ResolveAndroidTooling.RunTask()` ——
一个 NullReferenceException 伪装成资源错误，实际原因是 JDK 版本不对。

## 附录：如何使用无头实验台

```powershell
# 一次完整跑，看种群曲线和物种构成
dotnet Terrarium.Headless.dll --pop 220 --ticks 120000 --every 10000

# 多组种子做对照（判断一个改动是否稳健，而不是运气）
dotnet Terrarium.Headless.dll --repeat 8 --ticks 40000 --regen 0.0018

# 关闭水域做 A/B 对照
dotnet Terrarium.Headless.dll --repeat 5 --ticks 60000 --nowater

# 导出曲线和冠军基因组
dotnet Terrarium.Headless.dll --ticks 60000 --csv run.csv --export champion.json
```

参数一览见 `--help`。所有参数与 UI 里的环境面板一一对应 ——
**先用无头台找到好参数，再去 UI 里玩，这个流程能省掉大量来回。**
