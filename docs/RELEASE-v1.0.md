# 生态箱 Terrarium v1.0

一个**可编程的生物演化模拟**。

不是"养一堆会动的小点"——每只生物体内都有一份基因组、一张规则表和一个器官配置。
它们自己找吃的、躲天敌、产卵、养幼体；规则会变异，物种会分化，也会灭绝。
你改不了程序，但你能改它们的**规则**，然后看演化怎么处理你写的东西。

## 三十秒上手

1. 下载本页最下面的 **`Terrarium.exe`**（45 MB，自包含，**不用装 .NET**）
2. 双击。第一次启动会解压，慢几秒，之后正常
3. 按 **空格** 暂停/继续，点任意一只生物看它此刻在想什么

左上角是人口 / 物种数 / 昼夜。右边一栏是五个标签页：生物详情、规则编辑、物种、地形、环境。
勾上 **领** 能看到物种领地叠加层。

## 它到底在做什么

**每只生物有一份基因组**，包含 10 个器官等级（腿、眼、牙、甲、胃、藻胞、毒腺、生殖腺、鳃、棘）、
5 项生活史（寿命、繁殖间隔、幼体生命力、窝卵数、卵壳）和一张**行为规则表**。

规则长这样：

```
如果 [视野内的猎物距离] < 0.35 且 [自身体力] > 0.5
那么 [冲向最近猎物]
```

规则的左半边是传感器求值，右半边是动作。整张表每 tick 求值一遍，第一条命中就执行。

**变异有三层**：数值微调（器官等级 ±1）→ 规则参数微调 → 规则结构变异（换条件、换动作、增删规则）。
外加一个元演化层，调节变异率本身。

**物种是按行为指纹划的，不是按基因组编号。** 每只生物有一个 122 维指纹
（32 个固定探针下的行为输出 + 器官 + 生活史），子代指纹与物种模式标本的加权距离超过阈值就立新种。
颜色由物种 id 经黄金角映射，所以同物种永远同色、不同物种不撞色。

**生命有阶段**：成体产卵 → 卵有耐久（花点数买的性状）→ 被踩会碎 → 孵化出幼体 →
幼体要长大才能繁殖。一窝卵共享同一份子代基因组。

**世界是有结构的**：3200×2000，8 种地形。岩石不可通行，会**真的把世界切成互不连通的区域**，
这是物种分化最主要的推力。

## 注意事项

**这些不是 bug，是设计。**

- **地形是块状的，不是模糊的。** 地形位图只有 160×100，放大六倍铺满画布，
  用的是最近邻。用双线性会糊成一片看不出地形边界——这是特意换掉的。
- **画面里"没在动"可能是正常的。** 20 tick = 1 秒，一只生物走一格大约 15 tick。
  想看清就调倍速，想看演化就开一整夜。
- **别用界面调参。** 这是最重要的一条。生态参数的平衡**不可能靠看画面调出来**——
  一个改动是"变好了"还是"这次运气好"，只有跑多组种子对照才知道。
  项目里带了一个无头实验台就是干这个的（见下）。
- **exe 没有代码签名**，Windows SmartScreen 会拦一次。点"更多信息 → 仍要运行"。
- **快捷键**：空格暂停、滚轮缩放、双击跟随、`T` 开地形编辑。
  地形编辑模式下 `Shift+左键` 绘制、`右键` 擦除。

**如果你想认真玩这个工具，用无头实验台：**

```powershell
# 多组种子做对照 —— 判断一个改动是否稳健，而不是运气
dotnet Terrarium.Headless.dll --repeat 8 --ticks 40000 --regen 0.0018

# A/B 对照：关掉水域会怎样
dotnet Terrarium.Headless.dll --repeat 6 --ticks 40000 --nowater
```

## 缺点

**下面这些是真没做好的，不是谦虚。**

### 1. 长期共存仍然会收敛到 1–3 个优势种

这是**竞争排斥**的必然结果，不是调参能解决的：环境里只有一个限制性资源，
而且**没有硬取舍**——腿和眼在所有地形上都有效，鳃又很便宜。
没有"选了 A 就必须放弃 B"的结构，就不可能有稳定的生态位分化。

要真正解决需要互相排斥的生态取舍，那是一次更大的重设计，不是调几个数。
详见 `docs/DESIGN.md` 第 16.7 节。

### 2. 掠食者占比会飙到 69%，同时幼体占比偏高

某些种子里掠食者能占到种群的 69%，幼体占比 57–66%。
两个数字大概是一件事：**成体被大量捕食，种群结构因此偏年轻**。

试过调节捕食收益、攻击距离、卵的投资成本，都没能同时把两个数字压回合理区间。
**目前没解决。**

### 3. 点数预算没有起到设计中的作用

设计意图是让"我是谁"成为一道必须回答的题：20 点，用在移速、攻击、寿命、
繁殖间隔、幼体生命力、卵耐久上，**可以不用满但不能超**。

实测结果：演化稳定在 **12.6–13.6 点**，从来没逼近过 20。
原因是**用不满更划算**——省下的点数意味着更低的代谢开销，而少的那点能力不值那个价。

所以这个预算目前是个**软约束**，不是硬取舍。
它在"防止全能型"上有效（没有出现全 20 点的怪物），但没有产生设计时设想的张力。

### 4. Android 版没有在任何真机或模拟器上验证过

APK 能编译（0 警告 0 错误）、清单合法、已签名、Mono 运行时和两个 ABI 的 AOT 产物都在。
**但渲染正确性和触摸手感从来没被验证过。**

构建它的机器 CPU 不支持虚拟化（BIOS 里 VT-x 没开），也没有接真机，
模拟器根本启动不起来。这是整份代码里唯一一块没底的地方。

做了兜底：启动、渲染、模拟线程三条路径都包了 try/catch，出错会把原因直接画在屏幕上，
而不是留一片黑。但兜底不等于测试。

### 5. 其他没做的

- **没有有性生殖。** `Mutator.Crossover` 写好了，没接进流程，也没有 UI。
- **没有信息素场。** 想过，没做。这本来是解决第 1 条的一个可能方向。
- **没有谱系树。** 物种分化有记录，但看不到"谁从谁来的"。
- **生物不存盘。** 地图存档（gzip，约 150 KB）只存地形 + 肥力 + 配置，
  不存生物。所以跨平台重放只有"地图 + 种子"这一条路。
- **单机 2600 生物上限。** 实测 765 tick/s（8 线程并行感知-决策）。
  再往上加，感知成本会先爆掉。

## 项目结构

```
Terrarium/
├── src/
│   ├── Terrarium.Core/        模拟内核（纯 C#，零 UI 依赖，确定性）
│   ├── Terrarium.App/         WinForms 界面
│   ├── Terrarium.Android/     Android 界面（Canvas + 触摸）
│   └── Terrarium.Headless/    无头实验台（调参主力工具）
├── docs/DESIGN.md             完整设计文档（1200 行）
└── tools/                     两个 UI 冒烟测试脚本
```

**`Terrarium.Core` 没有任何 UI 依赖**——这不是洁癖，是有回报的：
Android 版移植时内核 5470 行**一个字节都没改**，从 `net9.0-windows` 换成 `net9.0` 就完事了。
重写的只有界面层。详见 `docs/DESIGN.md` 第 22 节。

## 确定性

**同样的种子，输出逐字节一致。**

这不是个形容词，是个可以验证的功能：随机数走 xorshift128+ 单流，
并行只用在感知-决策这种"只读世界、写自己"的阶段，执行阶段严格串行。

```powershell
# 同种子跑两次，CSV 和基因组 JSON 必须逐字节相同
dotnet Terrarium.Headless.dll --ticks 24000 --csv a.csv --export g.json
dotnet Terrarium.Headless.dll --ticks 24000 --csv b.csv --export h.json
```

这意味着**任何一次观察都可以被完整复现**——包括那些失败的实验。
调游戏平衡时这点比想象中重要得多：没有它，你分不清是改动起了作用还是这次运气不同。

## 构建

需要 .NET 9 SDK。

```powershell
# 桌面版
dotnet build src/Terrarium.App/Terrarium.App.csproj -c Release

# 发布单文件 exe
dotnet publish src/Terrarium.App/Terrarium.App.csproj -c Release -r win-x64 `
    --self-contained true -p:PublishSingleFile=true `
    -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true `
    -p:DebugType=none -o dist
```

Android 版另有两条硬约束（JDK 17、Android SDK 路径），见 `README.md`。
